- **Protocol values:** `src/core.dart:18` and `src/settings_routes.dart:23` return literal `cosmic`; `src/apply.dart:57` reports `done: ['cosmic']`. These are API data, not merely UI text.
- **Shortcut lifecycle outside shortcuts.dart:** `src/shortcut_routes.dart:7` constructs `ThemeShortcuts`; `src/auto.dart:619,632` uses it during rename/delete; `src/backup.dart:262,275` applies it during restore/rollback; `src/backup.dart:367` uses it for repair. Moving the implementation alone leaves these COSMIC paths active on KDE.
- **Preset semantics:** `src/workspace_state.dart:26,62,119` fixes ten workspaces and Tiled/Floating/Native modes; `src/workspace_state.dart:149` always applies per-workspace tiling. `src/presets.dart:322,360,403` assumes those operations during apply, capture and undo.

- **Persistent desktop state:** `src/apply.dart:81,88,92` stores/restores one shared `own_font`; `src/auto.dart:40,44` shares workspace/base-theme state across desktops. Switching desktop can restore another desktop’s font or stale workspace state.

Hiding top-level pages does not cover these.

**2. Interface, selection, gating and handover**

- **`wm watch` cannot fit the interface.** `docs/multi-desktop.md:42` returns one future/map; line 81 requires an indefinite event stream. Add a separate cancellable subscription/stream, including reconnect, initial snapshot and shutdown semantics.
- **The JSON contract is only partly neutral.** Focused-output numbering, nullable workspace membership and per-workspace `set-tiling` carry COSMIC semantics. Define stable desktop IDs versus presentation indices, sticky/multiple-desktop windows, activities, output changes and desktop removal. Existing restore matching assumes one integer workspace (`src/presets.dart:109,199`).
- **Capabilities are too coarse.** Separate workspace listing/events, window listing/moving/closing/activation, per-workspace tiling and overflow automation. A global tiling capability cannot satisfy `set-tiling <index>` (`src/workspace_state.dart:158`).
- **Unsupported and failed operations need distinct handling.** `src/workspace_state.dart:135` converts every helper error into `desktop_unavailable`. Preserve `not_available`, `not_found` and transport failures; reject unsupported requests before state changes.
- **Generic apply currently cannot work.** `src/apply.dart:52–55` requires successful desktop appearance before app templates at line 69. Define template-only success explicitly. Also resolve Generic `current()` without depending circularly on context/current theme.
- **RON conversion remains a COSMIC dependency.** `src/apply.dart:36` and `src/custom.dart:248` obtain conversion through the selected desktop. Separate format conversion from native application; specify helper packaging/failure behavior on KDE. Keep native RON application unchanged on COSMIC.
- **Selection needs precise rules:** exact colon-token matching, invalid-override errors, ambiguous-token policy, injected desktop precedence and consistent GUI/CLI/daemon environments. Never infer COSMIC from installed binaries. Enabling automatic selection in step 1 changes behavior immediately on this KDE machine.
- **Gate operations, not whole Presets.** Appearance-only presets already work independently (`src/preset_routes.dart:280,295`). Workspace presets need different capabilities from appearance presets. Preflight before `applySavedPreset` changes appearance at `src/presets.dart:306`; otherwise failure leaves partial changes.
- **“Read caps once” conflates support with availability.** Helper failure, KWin restart and plugin enablement can change availability. Keep structural capabilities stable and expose refreshable status. `terminalName` is also absent from the proposed metadata.
- **The handover is not implemented by adding a lock.** The existing applet never takes that lock and independently watches/runs automation (`cosmic/applet/src/main.rs:174,238,263,486`). Mixed old/new installations would duplicate actions. Require coordinated ownership, readiness, fallback and upgrade/rollback behavior.
- **Preserve existing automation guarantees:** queue coalescing/bound 64 (`main.rs:75`), startup marker consumed even when disabled (`:165,551`), 15-second tiling reconciliation (`:241`), cancellation after manual movement (`:250`), delayed initial membership (`:554`) and reconnect (`:486`). Tick must continue without a WM watch: step 3 precedes KDE WM support.
- Define session-specific ownership and prevent duplicate COSMIC/tray icons. Keep daemon ownership locking separate from the existing cross-process automation lock (`src/auto.dart:58`).

**3. KDE corrections and risks**

- **Color reload:** alternating names is justified: upstream explicitly skips an already-selected scheme and returns success. Alternate **file basenames**, choose against actual `kdeglobals` state, serialize writes/application, and verify results. Passing an arbitrary full path does not import it—the utility resolves an installed scheme by basename. [Upstream implementation](https://github.com/KDE/plasma-workspace/blob/master/kcms/colors/plasma-apply-colorscheme.cpp)
- **Wallpaper:** the utility changes every returned desktop containment and switches its wallpaper plugin to `org.kde.image`. Upstream also rejects apostrophes in filenames. Snapshot live containment/plugin/configuration state; restore through Plasma’s live API, not by replacing `plasma-org.kde.plasma.desktop-appletsrc` while plasmashell runs. Account for screens and activities. [Upstream implementation](https://github.com/KDE/plasma-workspace/blob/master/wallpapers/image/plasma-apply-wallpaperimage.cpp)
- **Konsole:** distinguish `.colorscheme` from `.profile`: the profile selects the scheme; the default-profile setting selects a profile. Preserve existing profile properties/inheritance and use a user override for system profiles. A changed default does not establish that existing sessions or explicitly selected profiles update. Specify and test live reload separately. Generate Konsole’s color groups, including intense/faint variants. [Scheme reader](https://github.com/KDE/konsole/blob/master/src/colorscheme/ColorScheme.cpp), [profile handling](https://github.com/KDE/konsole/blob/master/src/profile/ProfileManager.cpp)
- **Fonts:** `kwriteconfig6 kdeglobals General fixed` is not valid command syntax as written. Use `--file`, `--group`, `--key`; preserve the serialized QFont’s size/style fields and send the appropriate settings notification. Writing a family string alone is insufficient.
- **kglobalaccel:** `setForeignShortcutKeys` changes bindings; it does not supply a command executor for a new arbitrary component. Specify registered actions plus a persistent activation listener, or desktop-entry launch actions. Its key argument is `a(ai)`, not COSMIC/X11 modifier masks (`src/shortcuts.dart:21`). Preserve conflict detection and displaced-binding restoration. [D-Bus interface](https://github.com/KDE/kglobalaccel/blob/master/src/org.kde.KGlobalAccel.xml)
- **KWin external bridge:** `/VirtualDesktopManager` does not provide a window enumeration/control service. Scripts can enumerate windows, assign `desktops`, close windows and observe signals, but those signals do not automatically reach Dart. Define an explicit return/event bridge, request IDs, timeouts and script cleanup/reconnection. `callDBus` is asynchronous. `loadScript` returns a script ID; run the corresponding script object—loading alone is insufficient. Avoid spawning an accumulating script per polling request. [Scripting API](https://develop.kde.org/docs/plasma/kwin/api/), [script lifecycle](https://github.com/KDE/kwin/blob/master/src/scripting/scripting.cpp)
- **Krohnkite:** “per workspace not available” is too strong: maintained documentation supports layouts selected by output, activity and virtual desktop. That does **not** establish a stable external control API. Installed/enabled does not prove Maprisma can implement `set-tiling`; keep that capability off until demonstrated. Distinguish Krohnkite from KWin’s native manual tiling and test races with overflow moves. [Krohnkite documentation](https://github.com/anametologin/krohnkite#choose-layout-for-screen-by-default)

These upstream checks support the design risks; they are not live verification of this machine’s Plasma 6.8 behavior.

**4. Make step 1 a pure refactor**

- Move COSMIC code verbatim behind adapters; retain helper arguments, deadlines, errors, shortcut writes/shadow restoration, health response shape and automation JSON.
- Keep production selection COSMIC for this branch; add/test the selector without activating automatic selection until a separate behavior-changing step.
- Add `desktop.info` additively. Preserve existing protocol values and COSMIC UI behavior; keep the Rust applet and automation ownership untouched.
- Route **all** shortcut lifecycle callers through the seam, including backup rollback and health repair. Keep backup validation independent of an installed desktop.
- Add characterization tests for COSMIC apply/native RON, shortcut rename/delete/restore, health repair, preset apply/undo and unchanged automation output. Test unsupported-capability preflight with configurable fakes; unsupported calls must produce no writes, launches or desktop calls.
- Defer RON fallback, Generic template-only application, persistent-state namespacing and daemon handover to explicit behavior changes. Those cannot honestly be included under “no behaviour change.”
