1. **P1 — Live KWin failures are reported as success.** [desktop_kde.dart:195](/mnt/Data/Projects/maprisma-theme/packages/maprisma_theme_core/lib/src/desktop_kde.dart:195) ignores both effect-command failures and the final reconfigure failure. Missing `qdbus6`, an unavailable session bus, or a rejected load still returns `done: true`; the UI then reflects only the file. Also, `loadEffect` returns a **D-Bus boolean**, which checking the process exit code alone would miss. **Fix:** check transport results and verify the target state with `isEffectLoaded`/`loadedEffects`; treat already-loaded effects as success. Return an error when the requested live state cannot be reached. The [upstream Effects API](https://raw.githubusercontent.com/KDE/kwin/Plasma/6.4/src/org.kde.kwin.Effects.xml) confirms these return types.

2. **P2 — Partial writes leave the UI showing stale state after failure.** [desktop_kde.dart:191](/mnt/Data/Projects/maprisma-theme/packages/maprisma_theme_core/lib/src/desktop_kde.dart:191) can fail after earlier effects have already been written and unloaded. [settings_page.dart:144](/mnt/Data/Projects/maprisma-theme/flutter_app/lib/pages/settings_page.dart:144) simply returns on error, retaining the old switch values. **Fix:** snapshot the affected keys and live state, then roll back on failure; also refresh animation state after a failed setter. Disable the switches while a change is pending.

3. **P2 — Unknown state is displayed as enabled.** [settings_page.dart:129](/mnt/Data/Projects/maprisma-theme/flutter_app/lib/pages/settings_page.dart:129) converts a failed read into `{}`, while the switches at lines 360 and 366 interpret missing values as `true` through `!= false`. This presents a successful enabled-state read when none occurred. **Fix:** require actual boolean values and show disabled/unavailable controls with a retry path when state is unknown.

4. **P2 — A workspace “Off” switch does not cover other workspace animations.** [desktop_kde.dart:158](/mnt/Data/Projects/maprisma-theme/packages/maprisma_theme_core/lib/src/desktop_kde.dart:158) handles only Slide. A user with Fade Desktop enabled can still get transitions while this switch reads off, contradicting “Off switches at once.” The installed Plasma 6.8.2 includes `fadedesktop`, whose script handles desktop changes. **Fix:** either explicitly label this as the **Slide effect**, or include supported alternative desktop-switch effects in state detection and disabling.

Restoring `window: true` replaces a prior Glide/Fade selection with Scale. [settings_page.dart:145](/mnt/Data/Projects/maprisma-theme/flutter_app/lib/pages/settings_page.dart:145) does not offer Undo anyway, unlike the gaps/frame editor. **Fix:** if Undo is intended, return a receipt preserving each affected key—including absence—and restore those exact values through an Undo action.
