Found these concrete bugs. Paths below are relative to `packages/maprisma_theme_core/lib/src/` unless stated otherwise.

1. **[P1] Restoring one shadowed key can remove another active binding.** `shortcuts_kde.dart:283–286` saves the action’s entire key list separately for each borrowed key; `271–274` restores that entire snapshot. Scenario: another action owns keys A and B; Maprisma takes both, then releases only A. Restoring A also reinstates B while Maprisma still wants B. Releasing B later restores its intermediate snapshot, potentially deleting A again. Restoration needs to track individual borrowed sequences and merge with current state.

2. **[P1] Changing a binding can permanently lose its previous owner’s key.** `shortcuts_kde.dart:267–276` restores shadows before updating retained Maprisma components at `290–293`. Change one target from borrowed A to B: its component still owns A when restoration is attempted. The shadow record is then removed without checking that A was successfully restored. Updating the component subsequently frees A, but the recovery record is gone.

3. **[P1] Shortcut synchronization races can overwrite recovery records.** `shortcuts_kde.dart:202,225–288` has no serialization or lock. Every write launches an asynchronous sync, and the daemon can launch another. Two overlapping syncs can read the same shadow state, take different keys, and overwrite each other’s `kde-shadowed.json`. Removing the bindings then cannot restore the omitted key.

4. **[P1] Tray registration cannot recover after a watcher restart.** `daemon.dart:427–429` registers the same objects on every `_registerTray()` call. After the initial registration, `package:dbus` throws `Object already registered`; the retry at `448` swallows it before `RegisterStatusNotifierItem` is reached. Restarting plasmashell therefore loses the tray icon until the daemon restarts. This also affects startup when the watcher initially is absent.

5. **[P1] A hung core call permanently blocks automation.** `daemon.dart:372` awaits `core.call()` without a deadline or cancellation. A handler that never completes leaves `_busy` true indefinitely; workspace changes, wallpaper actions, ticks, and overflow jobs accumulate until the queue fills. The Rust applet’s process runner has a 60-second timeout and kills the child. Additionally, a hung autostart call at `451` prevents event subscription and timers from being installed.

6. **[P2] SIGTERM/SIGINT do not reliably terminate the daemon.** `daemon.dart:510–517` never cancels its signal subscriptions. Those listeners remain active after `done` completes, and handling the signals suppresses their normal termination behavior. The separately opened bridge connection at `desktop_kde.dart:53–54` is also never closed. The installer consequently can need its five-second SIGKILL fallback, while ordinary termination can leave a process alive.

7. **[P2] Bridge deadlines do not bound or cancel the complete request.** `kwin_bridge.dart:166–174` starts the deadline only after the serialized request reaches the front; `202–207` then awaits setup and cleanup beyond that deadline. `desktop_kde.dart:343` merely times out the caller’s future. Scenario: requests pile up behind a slow KWin operation; a queued move/close reports a timeout, then executes later when the queue advances. Watch setup and cleanup also have no explicit timeout.

8. **[P2] Multi-stroke shortcuts are corrupted during take/give-back.** `shortcuts_kde.dart:216–218` keeps only the first integer of each `QKeySequence`; `_keys()` at `213–214` reconstructs it with three zeroes. If an action has a borrowed single-stroke shortcut plus a multi-stroke alternative, taking the former already rewrites the latter as just its first stroke, and the saved recovery data cannot restore it. KDE’s API carries complete sequences as `a(ai)`. [KGlobalAccel interface](https://github.com/KDE/kglobalaccel/blob/master/src/org.kde.KGlobalAccel.xml)

9. **[P2] Menu refreshes never notify the host of changed layouts.** `daemon.dart:418–422` replaces menu data and increments its revision without emitting `LayoutUpdated`. Once Plasma caches a menu, changes to favorites or the current theme have no notification path. Refreshing inside `AboutToShow` also changes positional item IDs, so the host must be told to reload before subsequent clicks are interpreted.

10. **[P2] Batched menu events silently discard actions.** `daemon.dart:287–288` returns success for `EventGroup` without processing any events. A host sending a batched `clicked` event sees success, but applying a favorite or advancing the wallpaper never happens.

11. **[P2] The installed autostart command breaks for home paths containing spaces.** `tools/install-local:77` writes the absolute executable path unquoted into `Exec`. For `/home/Example User`, desktop-entry parsing treats `/home/Example` as the executable. The immediate restart uses shell quoting and can succeed, masking the failure until the next login.

The overflow search, queue bound/coalescing, manual-move cancellation, exclusive autostart marker, and bus-name single-instance check match the stated behavior. The added tiling-cap gates preserve COSMIC behavior. I found no concrete signature/type error in the normal StatusNotifierItem calls or `GetLayout` reply, and KDE’s lowercase `unregister(ss)` is valid. Shortcut commands currently restrict arguments to characters that avoid an additional Exec-quoting bug.

No files modified. This was a source review; I did not reproduce the scenarios in a live Plasma session.
